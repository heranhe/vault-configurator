## 导入核对：完整包数量、缺少文件清单、重复副本（2026-10-24）

用户反馈：模型文件夹有 733 个文件，导入后清单仍提示「本地缺 2 个」（含 x4 Runner Slides）。

原因：按文件名匹配时，同一模型若有多份副本（旧版 / 新版、重复解压到子文件夹），旧逻辑为避免用错版本一律不选，结果该零件被当作缺失；提示只折叠在弹窗底部的「同名待确认」里，导入提示又只写「723 个 STL」，用户无从判断。用 723 个文件（其中 x4 Runner Slides 多一份副本、x5 Runner Slides 缺失）的测试包在旧版线上复现：提示「723 个 STL，匹配 721 个模型」，与用户现象一致。

修复：
- 多份副本时，优先用与官方文件字节数一致的那份（目录 catalog.json 记录了每个官方文件的大小）；所有副本大小相同就用路径排序第一份；大小各不相同又都对不上官方文件时仍不猜，列为待确认。
- 导入弹窗说明「完整模型包共 723 个 STL 文件」；导入后显示核对卡片：完整包 723 个 · 已识别 N 个，缺少时列出每个缺少的文件路径并说明可以继续使用（缺少的零件显示为方块、打包时跳过），重复副本单独说明。导入提示同步改为「识别 N / 723 个模型，缺少 M 个」。
- 新增 4 项测试（相同副本、按官方大小选副本、无法判断时不猜、缺少文件逐个列出）。

验证：同一测试包在新版上显示「已识别 722 个，缺少 1 个：x5 Runner Slides」，重复的 x4 自动使用；完整文件夹显示「723 个 ✓ 文件齐全」。离线版与线上版均实测。177 项测试和生产构建通过；部署标识 665c3f8f，正式站首页、主脚本、样式 SHA-256 与快照构建一致，并在正式站重跑导入测试结果相同。
